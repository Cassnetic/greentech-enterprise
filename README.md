# GreenTech Enterprise — Booking MVP

Next.js 14 + TypeScript + Tailwind implementation of the GreenTech Prototype handoff.

## Features

**Customer**
- Landing page with two service tiles (Ro-Ro Bin · Lorry Delta)
- Single-page grouped booking form with live price calculation and date-availability check
- Receipt-first confirmation page with drag-and-drop payment proof upload

**Admin** (gated by NextAuth credentials)
- Kanban bookings board (drag cards across status columns)
- Payment review rail with one-click verification
- Booking detail drawer
- Availability calendar (click date to block/unblock, Sundays auto-closed)

## Stack

| Layer | Choice |
| --- | --- |
| Frontend | Next.js 14 (App Router) + TypeScript + Tailwind |
| Backend | Next.js API routes |
| Database | PostgreSQL + Prisma |
| Auth | NextAuth v5 (Credentials, JWT sessions) |
| Storage | Supabase Storage (payment proofs) |
| Email | Resend (booking confirmations) |

## Setup

```bash
cp .env.example .env.local
# Fill in DATABASE_URL, AUTH_SECRET (and optionally SUPABASE_*, RESEND_*).

npm install
npm run db:push           # apply schema to your Postgres
npm run db:seed           # seed admin user + 6 demo bookings + 3 blocked dates
npm run dev
# → http://localhost:3000
```

Demo admin credentials (pre-filled on the login form):
- Email: `admin@greentech.my`
- Password: `demo1234`

Override via `ADMIN_EMAIL` / `ADMIN_PASSWORD` env vars before seeding.

## Design tokens

CSS custom properties in `src/app/globals.css` mirror the prototype's `proto-tokens.css` (`--gt-bg`, `--gt-ink`, `--gt-accent`, radii, shadows, font stack). Tailwind config exposes the same tokens as `bg`, `ink`, `accent`, etc. for utility use.

## API surface

| Method | Path | Auth | Notes |
| --- | --- | --- | --- |
| `GET` | `/api/bookings` | admin | list all |
| `POST` | `/api/bookings` | public | create — re-validates price server-side |
| `GET` | `/api/bookings/:id` | public | fetch by ref |
| `PATCH` | `/api/bookings/:id` | admin | update `status` / `payment` (verifying payment on a pending booking auto-confirms it) |
| `POST` | `/api/bookings/:id/proof` | public | multipart upload, 10 MB limit, PNG/JPG/WEBP/PDF |
| `GET` | `/api/calendar/blocks` | public | list blocked dates |
| `POST` | `/api/calendar/blocks` | admin | block a date |
| `DELETE` | `/api/calendar/blocks?date=…` | admin | unblock |

## Notes

- Prices are authoritative server-side in `GT_PRICES` — the client total is recalculated on submit.
- `bookings.id` uses the `GT-0000` ref scheme, generated by max-plus-one on insert.
- Sundays are blocked in calendar UI only (no DB entries).
- Supabase / Resend gracefully no-op (with a console warning) if env vars are absent — useful for first-run local dev.
